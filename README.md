# Лаба 7

## Задание

Создать и заполнить динамическую матрицу по рекуррентной формуле. Напечатать её и статическую матрицу 10×10, ограничив длину строки 80 символами.

## Запуск


Ветка: `lab_7`. Задание: https://iu5git.github.io/cpp/meta/lab-07.html.
Код использует C++20. На macOS подходят Apple Clang и LLDB из Xcode.
WSL, Ubuntu и команды `apt` на Mac не требуются.

```sh
git switch lab_7
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
./build/lab_7
```

При переходе на другую лабораторную повторить конфигурацию и сборку.
CMake задаёт `-Wall -Wextra -Werror -Wpedantic` и стандарт C++20.
Список исходных файлов явно указан в CMakeLists.txt.

Проверки перед сдачей:


### Как показать и объяснить лабораторную 7

1. Выбери динамическую матрицу, введи `3 3`, точность `6`, формат `0`.
   Для x=1 текущая методичка даёт строки:
   `1, 0.5, 1/6`; `1, 1, 1/36`; `-1, -1/8, 1`.
2. Повтори с экспоненциальным форматом (1) и прямоугольной матрицей.
3. Выбери статическую матрицу 10×10 и покажи разбиение вывода на блоки
   столбцов: ни одна напечатанная строка матрицы не длиннее 80 символов.
4. Выбери объяснение указателей и сохранение матрицы в файл.

Формула взята с текущей страницы курса:
выше диагонали x^i/(j!)^i, ниже (-x)^i/(j!)^i, i,j начинаются с 1.
В старом README ветки стоит -x^i без скобок, поэтому для чётного i
результат отличается. В реализации используется текущая веб-методичка.

Вычисления рекуррентные: для следующего столбца обратный факториал
делится на номер столбца; для следующей строки степень домножается
на x/(j!). Ни pow, ни отдельное вычисление факториала не нужны.
Под диагональю знак отрицателен для нечётной строки и положителен
для чётной. На диагонали принудительно ставится 1.

Динамическая матрица — массив указателей на отдельно выделенные строки.
Статическая double[10][10] — непрерывный массив строк double[10].
Её нельзя приводить к double**: создаётся отдельный массив указателей
на начало каждой строки. Одна функция печати принимает оба вида матриц.
Память освобождается сначала у каждой динамической строки, затем у
массива указателей. Статическую матрицу через delete освобождать нельзя.

В строке задания с B подразумевается массив указателей на строки.
Первые адреса staticMatrix и staticMatrix[0] численно совпадают, но
имеют разные типы; staticMatrix[2] указывает на третью строку.
staticMatrix[0][0], **staticMatrix и *staticMatrix[0] дают 0.
*(*(staticMatrix+1)) и *B[1] дают 10.
*(staticMatrix[0]+1) и *(*staticMatrix+1) дают 1.

staticMatrix[0][20] и *(staticMatrix[0]+20) выходят за границы первой
строки: это неопределённое поведение C++, даже если физически строки
лежат подряд. Они показаны в комментарии и объяснении, но не исполняются.
Корректный доступ staticMatrix[2][0] и *staticMatrix[2] даёт 20.
