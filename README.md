# Лаба 4

## Задание

Реализовать сортировки выбором и пузырьком для статического и динамического массивов. Сравнить число сравнений и обменов.

## Запуск


Ветка: `lab_4`. Задание: https://iu5git.github.io/cpp/meta/lab-04.html.
Код использует C++20. На macOS подходят Apple Clang и LLDB из Xcode.
WSL, Ubuntu и команды `apt` на Mac не требуются.

```sh
git switch lab_4
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
./build/lab_4
```

При переходе на другую лабораторную повторить конфигурацию и сборку.
CMake задаёт `-Wall -Wextra -Werror -Wpedantic` и стандарт C++20.
Список исходных файлов явно указан в CMakeLists.txt.

Проверки перед сдачей:

```sh
cmake --build build --target clang-format clang-tidy
git status
git branch -vv
git remote -v
git log -3 --oneline
```

Цели проверок доступны, если CMake нашёл clang-format и clang-tidy.
В подготовленной локальной копии инструменты находятся в `.tools/bin`.
На другом Mac можно установить LLVM через `brew install llvm` и добавить
`$(brew --prefix llvm)/bin` в PATH перед конфигурацией CMake.
Для Linux CI использует clang-tools 18 и три независимые проверки.
Конфиги `.clang-format` и `.clang-tidy` сохранены из шаблона курса.
Точечные комментарии NOLINT объясняют ручную работу с памятью и указателями,
которую требует задание; остальные проверки продолжают действовать.

В VS Code открой папку репозитория. Локальные настройки `.vscode` уже
подготовлены, но исключены из Git согласно правилам курса.
`Cmd+Shift+B` собирает текущую ветку. Для отладки выбери в Run and Debug
конфигурацию этой лабораторной, поставь точку останова и нажми F5
(на клавиатуре Mac может потребоваться Fn+F5).
Для терминального показа используй команды выше: они не зависят от IDE.

После изменений и успешных проверок:

```sh
git add README.md CMakeLists.txt *.cpp
# Заголовки при их наличии также добавить через git add.
git commit -m "Update lab 4"
git push -u origin lab_4
```

Не добавляй `.tools`, `.vscode`, исполняемые файлы и папку build в коммит.
Зелёный CI подтверждается только на GitHub после успешного push.

### Как показать и объяснить лабораторную 4

1. Выбери пункт 1: программа напечатает исходный массив из 10 чисел
   диапазона 0–99, затем результаты обеих сортировок на трёх этапах:
   по возрастанию, повторно по возрастанию, по убыванию.
2. Продолжи выполнение и выбери пункт 2. Введи размер, например 1000.
   Для обоих методов используются одинаковые исходные значения.
3. Покажи отклонение размера 0, отрицательного числа, текста и дроби.
   EOF завершает программу, не вызывая бесконечный цикл.

`main` передаёт управление в RunApplication. PrintMenu выводит меню.
Выбор преобразуется в enum class Task и разбирается через switch.
Функции сортировки изменяют переданный массив и возвращают Statistics.
Считаются только сравнения значений элементов и фактические обмены
двух разных позиций. Проверки границ циклов в счётчик не входят.

Выбором: на каждом шаге ищем минимум/максимум оставшегося хвоста и
переносим его на своё место. Всегда n(n-1)/2 сравнений, не более n-1
обменов. Пузырьком: сравниваем соседей, меняем при нарушении порядка;
за проход крайний элемент занимает своё место. Если обменов нет,
завершаем раньше. Для уже упорядоченного массива n-1 сравнений,
для обратного порядка n(n-1)/2 сравнений и столько же обменов, если
все элементы различны. Оба алгоритма имеют худшее время O(n²),
но пузырёк имеет лучшее O(n). Дополнительная память сортировок O(1).

Динамические массивы выделяются через new[] и освобождаются delete[].
Обе попытки выделения проверяются, включая частичный отказ.
Размер ограничен 10000, чтобы квадратичные алгоритмы не зависали
на чрезмерно большом пользовательском вводе.
